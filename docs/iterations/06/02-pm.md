### F6-1. 來源無持股清單／無明細不算缺（優先 1，QA-01）

- 要解決的問題：

  - 程式目前把這些日子當成「尚未公布」，造成三個問題：
    - `check` 與排程持續回傳 1，`--notify` 每天通知一次。
    - 每次 `--catch-up` 都會白發請求。
    - 建議指令解決不了問題，會誤導使用者。
- 範圍內：
  - **判斷**：依分析師第三節的規則，從回應判斷三種結果。**不可以只靠日期清單或美國假日表判斷**。

### S9. `backup` 指令（優先 2）

- 要解決的問題：
  - 資料在容器的可寫入層（`MySqlServer` 的 `/var/opt/mssql` 不在 volume 內），`docker rm` 就全部遺失。
  - 處置／注意股歷史、主動 ETF 持股都無法完整重抓。
  - 第 3～5 輪都靠 PG 手動執行 `BACKUP DATABASE` 加 `docker cp`，指令散在各輪紀錄裡。
- 範圍內：
  - **指令**：`python -m twstock backup`。
    - 執行 `BACKUP DATABASE … WITH COPY_ONLY`（不影響其他備份鏈），可壓縮時壓縮。
    - 把備份檔從容器複製到主機資料夾，檔名含日期時間，例如 `TwStock_20261104_2130.bak`。
  - **輸出位置**：
    - 預設是專案上一層的 `_backups/`，沿用第 3～5 輪的位置，在 repo 外。
    - 可以用 `--out` 指定。
    - **只新增、不覆寫**：同名檔存在時要報錯，不得覆蓋。
  - **容器**：容器名稱可設定（SA 定案：參數、`.env` 選填變數，或自動偵測），預設相容使用者目前的 `MySqlServer` 與 `docker-compose.yml` 的 `twstock-mssql`。
  - **SQL Server 不在 Docker 裡時**（例如 Windows 本機安裝）：明確提示「備份檔留在伺服器端的路徑 …」，或支援直接寫到本機路徑（SA 定案）。不得出現 Traceback。
  - **驗證**：備份後執行 `RESTORE VERIFYONLY`（只驗證，不還原），印出檔案大小與驗證結果；失敗時 rc ≠ 0。
  - **容器內的暫存檔**：本指令自己產生的容器內 `.bak`，複製成功後可以刪除（SA 定案）。**容器內和 `_backups/` 原本就有的檔案一律不動**（包括第 3～5 輪的 3 份）。
  - **README**：
    - 新增「備份與還原」段落：`backup` 的用法、輸出位置、建議時機（改版或補抓前、每週一次）。
    - 還原步驟**只寫說明**（`docker cp` 進容器、`RESTORE DATABASE … WITH REPLACE`），並註明會覆蓋現有資料、請先停用排程。
  - **scripts**：`scripts/mac/`、`scripts/windows/` 可各加一個雙擊用的備份腳本（SA 判斷是否需要），**不得加入排程**。
- 範圍外：
  - 自動排程備份：使用者自行決定，README 可以提供範例。
  - 自動刪除舊備份。
  - `restore` 指令（風險高，不做成指令）。
  - 遷移到具名 volume（涉及停機，使用者決定）。
  - 雲端上傳。
- 驗收條件：
  1. `python3 -m twstock backup` 在 `../_backups/` 產生新檔：大小 > 75 MB，`RESTORE VERIFYONLY` 成功，rc=0。既有 3 份備份的大小與修改時間不變。
  2. 立刻再執行一次：產生另一個檔名，不覆寫。同名衝突（mock）時報錯，rc≠0，不覆蓋。
  3. `--out` 指定暫存資料夾可以正常輸出。
  4. 容器不存在、或 Docker 沒在跑時（mock）：明確訊息、rc≠0、無 Traceback。
  5. 資料庫連不上時：與其他指令相同，rc=2 並提示啟動。
  6. `msdb.dbo.backupset` 最新一筆 `is_copy_only = 1`。
  7. **PG 本輪的改表前備份就用這個指令**，`05-dev` 那種手動 SQL 不再需要；`04-dev.md` 記錄輸出。
  8. README、`__main__.py` docstring 與 `--help` 更新。
  9. **QA 不執行任何還原**，只用 `RESTORE VERIFYONLY` 驗證。
