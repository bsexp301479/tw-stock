## 八、缺陷與觀察

### 缺陷

無。

### 不列缺陷的觀察

1. **價差迷你圖的 0 軸在淺色模式很淡**：
   - 0 軸顏色是 `--border2`（淺色 `#cfcdc5`），白底上不容易看出，正、逆價差主要靠價差數字判斷。
   - 數字與文字都正確，不影響驗收。之後若要強化，可以加深 0 軸，或在 0 以下的區段換色。
2. **選股預設頁長 5.70 屏，第 13 輪 QA 記錄是 4.17 屏**：
   - QA 用同一份資料、同一個 375 × 812 視窗，把本輪前的網站檔（`logs/iter14_before/`）和本輪網站各量一次，**兩者都是 5.70 屏**（100 列，每列 37 px），所以不是本輪造成的。
   - 差異可能來自第 13 輪量測時的條件狀態不同。本輪改動不影響這一頁（預設欄位沒有營收或 EPS 年增欄）。
3. **設計文件的小誤**（程式正確，只記錄）：
   - 第八節說「沒有去年同月、但官方有年增」11/06 有 10 檔（例如 2867）。QA 以 `screen.json` 計算是 **2 檔**；2867 最後交易日是 08/19，不在 `screen.json` 內。不影響 `rb` 為 null 時不標示的規則。
   - 第 3-4 節「2 條換月虛線」實際 3 條，PG 已在 `04-dev.md` 記錄。
4. **選股「EPS年增」欄去年同季 ≤ 0 時顯示「--」，個股季報卡顯示「轉盈」**：這是本輪前就有的行為（例如 1808）。PM 要求「轉盈」的現有行為不變，本輪也沒有改，只記錄。

### 原文逐字檢查的說明

`logs/iter14_qa_verbatim.log` 最後一行是「有不符」，原因只有 1 個片段：季報進度那一行的「家）；本益比中位數會隨 EPS 更新而變動」。
- 這一行不是 `noteHTML` 說明，而是 F14-4 #3 刻意在括號內插入截止日。
- 「；本益比中位數會隨 EPS 更新而變動」仍逐字保留。
- 沒有 `due` 時，畫面和本輪前完全相同（mock 已確認）。
- 結論：符合設計，不是缺陷。
