## 二、設計

### 2-1 垂直位置：依標籤實際寬度（修 D33-QA-1）

- 原本的做法：
  - 只看「事件那根與左右各 2 根」的最高價。
- 改後的做法：
  1. 先決定水平位置。置中，靠邊時往內收，和原本相同。
  2. 找出和標籤水平範圍 `[left, left + w]` 有交集的每一根 K 棒。每根 K 棒的範圍是「中心 ± 半個間距」（`barSpacing / 2`）。
  3. 標籤底邊 = min（事件那根的箭頭上方 `y(H[i]) − 18`，範圍內每根 K 棒最高價位置 − 2）。
- 往內收的標籤會用收進去之後的範圍來找，所以 6465「11/24 調」這類靠邊的標籤也涵蓋在內。
- `evLabelPos(items, W, bars = [], h = 18)` 仍然是純函式。不傳 `bars` 時，結果和原本只看 `top` 相同，所以舊的位置、錯開測試案例都不用改。

### 2-2 錯開：放到相撞標籤的上方一層

- 原型實測發現新的狀況：
  - 改成依寬度找最高點之後，相鄰兩個標籤的底邊不一定一樣高。
  - 例如 6186「8/26 現增」比「8/6 息」低 14 px。照原本「固定往上 20 px」，還是會撞到，於是被隱藏。
- 改法：
  - 撞到時，放到「相撞標籤中最高那一個」的上方一層（`Math.min(...near.map(p => p.t)) − h − 2`）。
  - 還撞到，或超出圖的上緣，就不顯示文字，只留箭頭。這條規則不變。
- 兩個標籤底邊一樣高時，結果和原本相同。所以原本的錯開測試案例都照舊通過。

### 2-3 效能

- 每次定位時，要算全部 K 棒的座標：
  - 週 K 約 250 根。
  - 只做 `timeToCoordinate` 和 `priceToCoordinate`，沒有碰 DOM。
- 定位時機不變：捲動、縮放、改寬度、十字線移動後，等兩個 rAF。

## 三、原型實測（8001，副本）

### 量測方法

- 沿用 QA 的像素檢查：數每個可見標籤範圍內有幾個漲色、跌色的像素。
- 新增判斷：命中的像素如果只落在 1～2 列，就標成「價格線」，也就是最新價的水平虛線，不是 K 棒。
- **窗格在背景時 rAF 不會執行。** 量測時在頁面上把 `requestAnimationFrame` 暫時換成 `setTimeout`，每檔多等 2.5 秒，確認畫面已經重畫完才量。

### 結果

| 項目 | 補強前（QA） | 補強後 |
|---|---|---|
| 375 深，週 K，39 檔：標籤蓋到 K 棒 | 24 檔 | **0 檔** |
| 375 深，週 K，39 檔：標籤互相重疊 | 0 | 0 |
| 375 深，週 K，39 檔：被隱藏的標籤 | — | 0（6186、5274、2313 兩個都顯示） |
| 375 深，月 K，39 檔：標籤蓋到 K 棒 | 0 | 0 |
| 1024 淺，週 K，6 檔（2421、6465、4155、6195、6138、6186） | 3 檔有命中 | 0 檔蓋到 K 棒 |
| 00985B（`gx`）週 K／月 K | 顯示 12／10 | 顯示 11／11，0 處重疊 |

- 補強後仍有命中的情況：
  - 375 的 6464、1558，1024 的 6465、6195，以及 00985B 週 K。
  - 這些都只有 1～2 列像素，是最新價的價格虛線從標籤下面穿過，K 棒沒有被遮住。
- 更正 QA 的數字：
  - QA 報告裡 1024 淺色的 6465「104」、6195「102」也是價格線，不是 K 棒。
  - 1024 實際蓋到 K 棒的只有 4155 這一檔。
- 截圖確認：
  - 6138「7/31 息」移到最高點 420 之上，高點完整可見（1024 淺）。
  - 6186 兩個標籤上下錯開一層，都顯示。
