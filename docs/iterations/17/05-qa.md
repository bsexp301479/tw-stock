## 四、缺陷與觀察

### 缺陷

### 不列缺陷的觀察

1. **「已達條件」後來被處置的比例，實際畫面比設計 3-3 寫的更低，但「差一次」有提前提示的效果**：
   - 設計 3-3 說：10/26 起上市「已達條件」5 次，其中 2 次 3 日內被處置（2466、4526 10/29）。
     - 這 2 次的「已達條件」發生在處置公告當天。實際匯出時，當天已收到處置公告，這兩檔會進「即將處置」組，不會出現在預警中。
     - QA 照實際畫面的排除規則重算：10/26 起「已達條件」5 次（2424 ×2、3167、2360、3532），後 3 個交易日內被處置 **0 次**。2360、3532 是 11/06 的，還沒有後續資料。
   - 但 3 次上市處置**在前一個交易日都已經列在「差一次」**：
     - 2466、4526 在 10/28：第一款連 2 日。
     - 6213 在 11/02、11/03：10 日內 5 次。
   - 所以這個組真正有用的是「差一次」：可以提前一天提醒。「已達條件」卻沒被處置，代表官方可能另有條件我們不知道，見設計 3-3。
   - 建議：畫面已標「推算」與「以官方公告為準」，不必改。B10-延伸c（12 月以後）統計命中率時，要用「差一次 → 隔日處置」和「已達條件 → 後 3 日處置」兩種口徑。
2. **Q17-1 尚未驗證**：
   - `COUNT_DOWN = True` 時 2360、3532 是「已達條件」（3 天裡有第一款跌幅）；`False` 時 0 檔。
   - 11/09 收集後，若 2360、3532 都沒有處置公告、到 11/10 也沒有，傾向官方只算漲幅。那時改成 `False` 只要改一個常數，`test_count_down_switch` 兩種值都有測。
3. **單元測試的款別到第十三款**：PM 驗收 #5 寫「一～十四」。
   - 解析邏輯對「十X」都一樣，QA 獨立驗算也用字串比對了全部注意列（含第十四款以外的實際款別），0 筆不同。
   - 不補測試。
