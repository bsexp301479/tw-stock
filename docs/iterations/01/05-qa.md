### QA-01（中）MI_INDEX 指數表欄位改名或列長度不足時，整日行情收集失敗

- 相關檔案：`twstock/collectors/daily.py:29`、`:32`、`:33`、`:35`（`parse_taiex` 用 `idx["…"]` 和 `row[...]` 直接取值）；`twstock/collectors/daily.py:47`（`fetch_twse_daily` 在解析個股**之前**呼叫 `parse_taiex`）。
- 重現步驟：
  ```bash
  python3 -c "
  from datetime import date
  from twstock.collectors.daily import parse_taiex
  t={'tables':[{'title':'115年10月29日 價格指數(臺灣證券交易所)','fields':['指數名稱','收盤指數','漲跌(+/-)','漲跌點數'],'data':[['發行量加權股價指數','1','-','1']]}]}
  parse_taiex(t, date(2026,10,29))"
  ```
  結果丟出 `KeyError: '指數'`。如果欄位名稱沒變但資料列比 fields 短，會丟 `IndexError`。
- 預期：PM A1「指數收集失敗不可影響當日股票資料寫入」，以及設計「共通約定」的「解析一律用 `row.get()`，欄位缺漏時略過該列，不丟 `KeyError`」。也就是應回傳 `None`，個股照寫，並印「⚠️  MI_INDEX 找不到加權指數表」。
- 實際：例外從 `fetch_twse_daily` → `collect_for_date` 一路往外拋，而 `cmd_collect` 只攔 `FetchError`，結果**整個 `collect` 中斷，當日上市／上櫃行情、法人、匯出全部沒有執行**。原本與指數無關的每日收集，因為多了指數解析而多了一個失敗點。
- 建議修法：在 `parse_taiex` 內做防護，例如先確認 `{"指數","收盤指數","漲跌(+/-)","漲跌點數"} <= idx.keys()`，不符合就 `continue`；資料列長度不足時略過。或者用 `try … except (KeyError, IndexError): return None` 包住整段。修完後在 `tests/test_iter01.py` 的 `test_parse_taiex` 補上「欄位改名 → None」「列太短 → None」兩個斷言。
- 備註：SA 設計稿的 `parse_taiex` 範例本身就是這個寫法，PG 照抄了；但它與同一份設計的「共通約定」矛盾，應以共通約定為準。

### QA-02（中）手機 375px 下月營收表格超出卡片寬度，「累計年增」欄被切掉

### QA-03（低）月營收折線的 hover 格式 `+.2f` 被 Plotly 判定為無效格式
