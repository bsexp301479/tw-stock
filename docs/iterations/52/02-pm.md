## 需要使用者決定的事項

### D219 `history --only financials` 要不要連資產負債表一起抓

- 現況：D208 = A 把資產負債表附掛在 `collect_financials`；`history --only financials`（`run_financials`）也是呼叫 `collect_financials`，所以**之後重抓季報時每個（季別 × 市場）會變成 2 次請求**。`test_iter10.py:291` 用 `lambda *a` 取代 `collect_financials` 並逐字比對 `calls == [(2026, 3, None, ("TPEx",))]`，所以不能用加關鍵字參數的方式在回補時關掉附掛（會讓這行舊測試失敗）。
- **A**：接受連帶結果；`run_financials` 只改預估那一行為「每次另抓資產負債表」並把時間乘 2（二之一 C）。重抓季報時資產負債表也一起更新，兩張表同一天的數字一致。舊測試 0 行。
- **B**：只在每日收集時附掛（`collect_financials` 以 `first_seen` 有值判斷；補抓一律傳 None），`history --only financials` 請求數不變，資產負債表只能用 `--only balance` 補。舊測試 0 行，但「有沒有附掛」藏在一個參數的意義裡，之後讀程式的人不容易看出來。
- **預設 A**：`history --only financials` 平常很少跑（只在重抓或補缺），請求加倍的影響小，而且畫面上的預估時間會跟著改正；B 讓同一個函式在兩種情境做不同的事，較不直觀。
