## 五、缺陷

### QA28-01（中）同一頁內重畫並改網址後，返回不會還原捲動位置

- **重現步驟**（1024 或 375 皆可，請用滾輪捲動）：
  1. 開 `#/rank/n+`（此時 `history.state` = `{k: …}`）。
  2. 點「5日」（或上市／上櫃、成交額門檻、金額單位）。`renderRank()` 不帶參數執行，`arg !== by` 成立，執行 `history.replaceState(null, '', '#/rank/' + by)` → `history.state` 變 `null`。
  3. 滾到 `scrollY` 800，點任一檔（實測 6446）進個股頁。
  4. 按返回：排行回到 **0**（期望 800）。
  - 同樣機制（都在 `route()` 之外呼叫 `replaceState(null, …)`）：
    - 選股改條件：`app.js:1270` `draw()` 每次 `history.replaceState(null, '', '#/rank/screen?' + …)`（實測勾一個條件後 `history.state` = `null`）。
    - 今日切分頁：`app.js:239`（程式確認，與排行同理）。
    - 個股切分頁：`stock.js:225`（設計 D28-03 已列為已知限制；實測走勢 → 籌碼、捲到 500 → 排行 → 返回：0）。
- **影響**：U28-01 的主要情境是「排行／選股清單 → 個股 → 返回」，使用者在排行切 1日／5日、在選股調條件是常見操作；一旦切過，該頁就退回舊行為（返回到頂端），而且沒有任何提示。沒有資料錯誤。設計只預告了個股分頁一種情況，影響比「小」大。
- **原因**：捲動位置記在 `scrollAt[scrollKey]`，`route()` 回來時讀 `history.state?.k`。上述 4 處在 `route()` 結束後才把 state 換成 `null`，`scrollKey` 仍是舊鍵（捲動照樣記錄），但瀏覽紀錄上已經沒有鍵，返回時找不到。
- **建議修法**（約 1 行，不動任何被測試鎖定的字面：`test_iter12` 的分頁切換、`test_iter27:108、110` 的 `replaceState(null, …)` 都不必改）：
  - 把 `init()` 的捲動監聽改成「記位置時順便把鍵補回目前這筆紀錄」：
    ```js
    addEventListener('scroll', () => { if (!scrollKey) return; scrollAt[scrollKey] = window.scrollY; if (history.state?.k !== scrollKey) history.replaceState({ k: scrollKey }, ''); }, { passive: true });
    ```
    `route()` 執行中 `scrollKey` 是 `null`，不會干擾換頁；`replaceState` 不帶網址，保留 4 處剛改好的網址；只有鍵不一致時才呼叫（每次切換後第一次捲動補一次）。
  - 若要連「切換後完全沒捲動就離開」也涵蓋，可再在 4 處 `replaceState(null, …)` 的下一行加 `history.replaceState({ k: scrollKey }, '')`（`scrollKey` 在 `app.js` 頂層，`stock.js` 可直接讀到），但要動 4 個檔案位置，收益不大。
  - 補測：`test_iter28.test_route_scroll_restore` 的 node 測試可加一段「`route()` 後把 `history.state` 設成 `null`、觸發 `scroll`，`history.state.k` 應恢復」。
  - 修後複測：排行切 5日 → 捲 → 個股 → 返回；選股勾條件 → 捲 → 個股 → 返回；個股切籌碼 → 捲 → 排行 → 返回；今日切期貨 → 捲 → 泡泡 → 返回。另外重跑 D28-03 表格前 4 列，確認原本通過的情境沒變。
- **嚴重度**：中（主要功能在常見操作後失效、無提示；不影響資料正確性，可用重新捲動自行恢復）。
