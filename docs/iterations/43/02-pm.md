## 二之一、F43-1 收集

### 資料表 `share_distribution`（`setup-db` 建立，可重複執行）

- 股票與 ETF **同一張表**，用代號字串＋`is_etf`（比照第 40 輪 `dividend_notices`，不用外鍵）；寫入時只收 `stocks`、`etfs` 表已有的代號。PM 決定，理由：同一份官方檔、同一個鍵、匯出一次查詢就分得開。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | BIGINT IDENTITY PK | 比照 `foreign_holdings` |
| `code` | NVARCHAR(10) NOT NULL | 股票或 ETF 代號（已 `strip()`） |
| `is_etf` | BIT NOT NULL | 依寫入時命中 `etfs` 表判斷 |
| `data_date` | DATE NOT NULL | **官方檔的「資料日期」**（每週最後一個營業日），不是抓取日、也不是程式推算的目標日 |
| `n1` ～ `n16` | INT NOT NULL | 1～16 級人數（最大值 0050 1 級 1,644,997，INT 足夠） |
| `s1` ～ `s16` | BIGINT NOT NULL | 1～16 級股數（0050 合計 255 億股，超過 INT） |
| `n_total` | INT NOT NULL | 17 級（合計）人數 |
| `s_total` | BIGINT NOT NULL | 17 級（合計）股數，> 0 |
| `fetched_at` | DATETIME NOT NULL DEFAULT GETDATE() | 寫入時間 |
| 唯一鍵 | `UQ_share_distribution (code, data_date)` | |
| 索引 | `IX_share_distribution_date (data_date)` | 取最新一週、近 52 週用 |

- 不存官方「占集保庫存數比例%」（可由股數重算，差 ≤ 0.01 個百分點，R48）。
- 估計：每週約 2,360 列（股票 1,992＋ETF 367），一年約 12.3 萬列、約 25～30 MB。

### 解析 `parse_tdcc(text)`（純函式，可單獨測）

| 規則 | 內容 |
|---|---|
| 解碼 | `resp.content.decode("utf-8-sig")`（去 BOM）；以 `csv` 模組讀 |
| 表頭 | 必須正好是 `資料日期`、`證券代號`、`持股分級`、`人數`、`股數`、`占集保庫存數比例%` 6 欄（每欄 `strip()` 後比對）→ 否則 `SchemaError` |
| 資料列 | 0 列 → `SchemaError`（「沒有資料列」）；某列欄數不是 6 → `SchemaError` |
| 資料日 | 8 碼西元 `YYYYMMDD`；整份檔必須只有 1 個資料日 → 否則 `SchemaError` |
| 代號 | `strip()`（官方右邊補空白到 6 碼，例 `'2330  '`、`'00878 '`） |
| 分級 | 每個代號 1～17 級各恰好 1 列（含不收的代號）→ 缺級或重複 → `SchemaError`（整份不寫） |
| 保留的代號 | `is_valid_stock_code(code) or is_etf_code(code)`；其餘（`2881A` 特別股、`01001T` 受益證券、TDR 等）不收、不驗算 |
| 數字 | 人數、股數必須是不帶小數的非負整數；比例欄不讀 |
| 合計驗算（R46，只對保留的代號） | 人數：1～15 級和 = 17 級；股數：1～15 級和 − 16 級 = 17 級；17 級股數 > 0。任一不成立或數字不是非負整數 → **略過該代號並計數**，不中止整份 |
| 輸出 | `(data_date, rows, skipped)`；`rows` = `[{code, n1..n16, s1..s16, n_total, s_total}]`，`skipped` = 略過的代號數 |

- `000218`：`is_etf_code` 為真、會留在 `rows`，但 `etfs` 表沒有 → 寫入時排除（驗收要測）。

### 寫入 `collect_tdcc(latest, today)`

- `latest` = 表中最大 `data_date`（None = 空表）。
- 官方資料日 **>** `latest`（或 `latest` 為 None）→ 一個 MERGE（OPENJSON，同一個交易）寫入 `stocks`、`etfs` 已有的代號；`is_etf` 由命中的表決定；同鍵存在時整列覆寫（理論上不會發生，Q43-5）。
- 官方資料日 **≤** `latest` → 不連資料庫、不寫入（官方尚未更新或回退）。
- 0 列可寫（全部代號都不在本站）→ 不連資料庫；算成功，輸出照印（股票 0、ETF 0）。
- 回傳給 `execute_plan` 的紀錄（寫進 `collect_runs.detail.undated.tdcc`）：

| 情況 | `undated["tdcc"]` |
|---|---|
| 寫入新的一週 | `{"on": "2026-11-23", "d": "2026-11-20", "s": 1992, "e": 367}`（`s`、`e` = 實際寫入的股票、ETF 檔數） |
| 官方尚未更新 | `{"on": "2026-11-28", "d": "2026-11-20"}`（沒有 `s`、`e`） |
| 失敗 | 沒有 `tdcc` 鍵；`errors["tdcc"]` 有例外 |

### 抓取時機（`make_plan` 加 `tdcc`）

- **只有 `collect --catch-up`**：`plan_for_date`（`collect --date`）不加這個鍵；`history`、`events` 子命令不抓。
- **資料表存在才排**（PM 決定，理由見二之四與風險）：`_run_locked` 第一次連線時取得 `(表是否存在, 表中最大 data_date)`，以**新的關鍵字參數**傳給 `make_plan`（預設 None = 不排 `tdcc`；舊測試以位置參數呼叫 `make_plan`，結果不變）。
  - 存在判斷用 `OBJECT_ID('share_distribution')`；`fetchone()` 為 None 或值為 None 都當作「不存在」。
  - 表不存在時：收集**不印任何字**、不發請求（`check` 會提示執行 `setup-db`）。
- 目標週（純函式，`collectors/tdcc.py`，收集與 `check` 共用）：

```text
wk(d)  = d 所在週的週一（d − d.weekday() 天）
t      = 今天以前（不含今天）最後一個交易日（依 load_closed 的 closed）
若 wk(t) == wk(今天)，且 [今天, wk(今天) + 4 天] 之間還有交易日（含今天）
       → 這週還沒過完，t 改為 wk(t) 之前最後一個交易日
target = wk(t)            # 最近一個「已經過完、而且有交易日」的週
```

- 排 `tdcc` 的條件（全部成立）：
  1. 表存在；
  2. `latest` 為 None，或 **`wk(latest) < target`**（比「週」，不比日期）；
  3. `state.get("tdcc_on") != 今天`（`load_state` 由最近一筆有 `undated.tdcc` 的紀錄取 `on`；舊 state dict 沒有這個鍵 → 視為沒抓過）。
- **為什麼比週不比日期、寫入用官方資料日**：預先不知道的颱風休市（例：週五臨時休市還沒進 `closed`）時，程式推算的最後交易日是週五，官方資料日是週四；比日期會變成「永遠比目標舊、每天重抓」。以官方資料日寫入、以週比較，週四、週三提前都不受影響。`market_holidays`／`AD_HOC` 只用來決定「這週過完了沒」，不用來決定資料日。
- `plan_is_empty` 要把 `plan.get("tdcc")` 納入（只有 `tdcc` 要做時也要執行 `execute_plan`）。
- `make_plan` 的 `tdcc` 判斷放在 `if not days: return plan` **之前或與之無關**（週末、休市日也要能排）；用 `plan["tdcc"] = …` 另起一行，**不要改 `plan` 字面那一行**（`test_iter40` 反證依賴 `"financials": None, "notices": False}` 這段字面）。

### 執行順序、失敗隔離

- `execute_plan`：在 `notices` 迴圈之後、`revenue` 之前，`if plan.get("tdcc") and _guard("tdcc", errors, …)` 成功才寫 `undated["tdcc"]`。
- 請求：`request("GET", "https://opendata.tdcc.com.tw/getOD.ashx?id=1-5", expect_json=False, isolated=True)`；不重試、不標記主機；節流沿用 `DEFAULT_INTERVAL` 3 秒（每次執行最多 1 次）；不用 OpenAPI 的 JSON 版（R43）。
- 失敗（HTTP 錯誤、逾時、`SchemaError`、解析錯誤）：只印 `_guard` 既有格式 `  ⚠️  tdcc 失敗：…`；**不列入 `undated_errors`**（不算異常、不發通知、回傳碼與 `result` 不變）；沒有 `undated.tdcc` → 下一次執行（不論同一天）再試。
- 資料庫錯誤（`pyodbc.Error`）不在 `_guard` 範圍，照既有流程走 `_db_failed`（比照第 40 輪）。

## 二之二、F43-2 匯出 `sh`

### 選列

1. 表不存在 → 不讀、全部不輸出（匯出不因新表未建而失敗；理由見風險）。

### 欄位格式（逐字）

```json
"sh": {"d": ["2026-11-20", "2026-11-27"],
       "b": [63.33, 63.45], "k": [51.97, 52.01], "m": [13.68, 13.6], "r": [22.99, 22.95],
       "n": [53095, 53407], "bn": [100, 101], "z": [32045, 32210]}
```

（第二週的數字是示意。）

| 鍵 | 內容 | 計算（R48） |
|---|---|---|
| `d` | 資料日 `YYYY-MM-DD`，舊到新 | `data_date` |
| `b` | 持股超過 400 張的股數比例 % | (s12＋s13＋s14＋s15) ÷ `s_total` × 100 |
| `k` | 持股超過 1,000 張 % | s15 ÷ `s_total` × 100 |
| `m` | 超過 50 張至 400 張 % | (s9＋s10＋s11) ÷ `s_total` × 100 |
| `r` | 50 張以下 % | (s1＋…＋s8) ÷ `s_total` × 100 |
| `n` | 總人數（股東或受益人） | `n_total` |
| `bn` | 持股超過 400 張的人數 | n12＋n13＋n14＋n15 |
| `z` | 未滿 1 張（零股）人數 | n1 |

- 比例**用股數自己算**，分母 = 17 級股數，**整數運算四捨五入到 2 位**（例：`(2 × 和 × 10000 + s_total) // (2 × s_total)` 再 ÷ 100），JSON 數字去尾 0（`28.90` → `28.9`）；不加總官方比例、不用 `stocks.shares`。
- `b + m + r` 不一定等於 100（16 級不是 0 時會超過，例 00406A 100.35），不調整。
- 7 個陣列和 `d` 等長；人數是整數。
- 位置：個股 dict 在 `"fh"` 那行之後；ETF 在 `E["nx"]` 之後以 `E["sh"] = …` 附加（放在最後）。`etf_export` 簽名不改。
- **沒有任何週的代號不輸出鍵**，檔案和改版前逐位元組相同；表不存在或空表時所有 `stocks/`、`etfp/` 檔案逐位元組不變。
- 大小：每週一點約 50 bytes，52 週約 2.5 KB／檔；上線初期幾乎不變。
