## 四、風險與相依性

### 風險

1. **改既有表 `price_events`**：
   - 對策：`backup` 在先；只加可為 NULL 的欄位；`setup-db` 兩次；SQL 比對既有欄位逐值不變（F19-1 #1、#2）。
2. **回補用 MERGE 覆寫**：官方若修正過某筆前收或參考價，回補會改到既有值，還原價跟著變。
   - 對策：回補前後 SQL 比對既有欄位；有差異逐筆記在 `04-dev.md`，並說明對還原價的影響；不自行還原，回報使用者。
3. **官方改欄名**：「減除股利參考價」找不到時不能讓整批事件失敗（除權息是還原價的來源）。
   - 對策：欄位找不到存 NULL；畫面退回「除權」；單元測試（F19-1 #7）。事件收集本來就由 `catchup.py` 的 `_guard` 隔離，不影響行情等其他資料。
4. **容差判斷錯誤**：參考價有四捨五入；高價股（6669 的 7,800）與低價股都要對。
   - 對策：容差 0.005 元（SA 可調，寫明理由）；櫃買 112 筆真值測試；全表獨立重算。
5. **週／月 K 標記擠在一起**：加日期後文字變長，手機上可能重疊。
   - 對策：F19-2 #8；SA 可在月 K 或窄螢幕時縮寫。
6. **多事件、面額變更的漲跌**：比值相乘的順序、前一根無成交。
   - 對策：單元測試涵蓋；6949、8422 實例驗收。
7. **使用者收集與 PG 重疊**：使用者可能在 PG 回補期間跑 `collect --catch-up`（也會寫 `price_events`）。
   - 對策：每一步記錄 `collect_runs` 最大 `run_id`；若有新收集，SQL 比對以 `run_id` 前後分開說明；匯出比對允許 `ev` 多分類鍵。
8. **環境**：測試用 8001，結束時關閉；不動 `.env`、`_archive/`；不安裝排程；本輪是否 commit 由使用者決定。

### 相依性

- F19-2 的標記文字（「2/24 現增」）依賴 F19-1 的分類；PG 先做 F19-1 再做 F19-2。若 F19-1 回補失敗，F19-2 照做，標記退回「2/24 權」。
- PG 順序見第一節「3. 上線順序」：**backup → setup-db → 回補 → export**。
