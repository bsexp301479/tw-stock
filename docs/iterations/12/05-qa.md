## 三、QA 獨立核對

### 1. 唯讀 SQL（`logs/iter12_qa_sql.py`／`.log`）

- 加權本益比：SQL 依日期、市場加總（只計本益比 > 0、股數 > 0、收盤 > 0），QA 自己算位置、範圍、覆蓋率、最大權重。兩市場 6 個值全部相同。
- ETF 借券：各市場最新日，先加總股數再換張；合計與逐檔都相同。
- 市值、週轉率：SQL 取最後一個非空收盤與當天成交量，逐檔比 `screen.json`；`mt` 抽查 4 檔；「沒有股數的個股」= 「沒有 `mt` 的個股」（9 檔）。
- 週轉率排行：同門檻前 10 名。

### 2. QA mock（`logs/iter12_qa_mock.py`／`.log`，8 項）

1. 呼叫端把本益比、市值轉成 float（資料庫回傳 Decimal；`market_wpe` 的合約是 float）。
2. 窗口空 → 不輸出。
3. 三天持平 → 位置 100%、最低 = 最高。
4. 市值最大的是虧損股 → 權重取計入股票中最大的，覆蓋率正確。
5. 借券列有、但當天行情沒有的 ETF → 不新增列。
6. 借券餘額減到 0、增減 −1,500 股 → −2 張（正負對稱）。
7. 0 成交 → 週轉率 0.0。
8. Decimal 收盤 → 市值正確。

- 說明：第 1 項 QA 原本直接傳 Decimal 進 `market_wpe`，會 `TypeError`；查證後呼叫端已先轉 float（`_load_valuation`），是 QA 的假設錯，不是程式缺陷，改成檢查呼叫端。

## 七、缺陷與觀察

### 缺陷

| 編號 | 嚴重度 | 內容 | 建議修正 |
|---|---|---|---|
| D1 | 輕微（文件） | README 條件選股一段寫「`to` 週轉率（…，今天沒有成交為 null）」。實際上沒有成交的股票當天在 `daily_prices` 仍有一列、成交量 0，所以 `to` = 0（`screen.json` 中 `to` 為 null 0 檔、為 0 的 32 檔）。設計第八節「今天沒有成交 → 週轉率 null」也是同一個誤解。程式行為（0%）本身合理：沒有成交，週轉率就是 0 | README 改成「今天沒有成交為 0」；程式不用改 |

### 不列缺陷的觀察

1. **市場市值合計和分析師不同**（只用來驗算，網站沒有顯示）：
   - 網站口徑（最後一個非空收盤）：上市 1,299,543 億（1,091 檔）、上櫃 84,843 億（892 檔）。
   - 分析師口徑（只用 11/06 收盤）：上市 1,299,526 億、上櫃 84,455 億，和 PM 數字相同。
   - 差異來自 11/06 沒有成交的 19 檔（上市 2、上櫃 17）：分析師沒有計入它們的市值，網站用它們的上一個收盤。檔數相同是因為這些股票當天仍有資料列。網站口徑符合設計 4-1，個股頁也需要這樣才有市值可顯示。
2. **加權本益比的「一年最低」判斷優先於「一年最高」**：窗口內每天都相同時（實務上不會發生），會顯示「一年最低」。和既有中位數的寫法一致，不改。
3. **ETF 頁借券欄的逐檔加總剛好等於合計**（11/06 上市、上櫃都相同）；一般情況下兩者可能差幾張（先加總股數再換張），設計 3-1 已說明。
