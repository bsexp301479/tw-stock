## 二、匯出（F35-1）

### 2-1 欄位

| 欄 | 型別 | 意義 | 沒有時 |
|---|---|---|---|
| `dvd` | 字串 `YYYY-MM-DD` | 近 365 天內最近一次「息」或「權息」的除息日 | `null` |
| `dvp` | 數字 | 該次的除息前收盤（`dv` 的 `p`） | `null` |
| `dvn` | 整數 | 已填息時的填息天數（`dv` 的 `n`） | `null`（未填、中斷） |
| `dvx` | 字串 | 中斷原因（`dv` 的 `x[1]`，例如「配股」「減資」） | `null` |
| `dvk` | 整數 | 近 365 天「息」「權息」次數 | `0` |

```python
def div_screen(dv, today):
    y = [r for r in dv if r["t"] != "權" and (today - date.fromisoformat(r["d"])).days <= 365]
    r = y[-1] if y else {}
    return {"dvd": r.get("d"), "dvp": r.get("p"), "dvn": r.get("n"), "dvx": (r.get("x") or [None, None])[1], "dvk": len(y)}
```

- 「近 365 天」含第 365 天（`<= 365`），以資料日 `latest_date` 為準。
- 純配股的「權」不算：最近一次是純配股時，取它之前的那次息。

### 2-2 接線：為什麼 `dividends()` 呼叫兩次

- 第一版把 `dv` 先存成變數，給個股 JSON 和 `screen` 共用。但這會改到兩行被舊測試逐字鎖定的程式：
  - `test_iter24:225` 鎖 `"dv": dividends(d_, c, ev, events.get(code, [])),`。
  - `test_iter18:91` 鎖 `**osc_stats(o, h, l, c, af)}`（必須是 dict 最後一項）。
- 定案：個股 JSON 那行**完全不動**；`screen` 在 `osc_stats` 前一行用同一組參數再呼叫一次：

```python
**div_screen(dividends(d_, c, ev, events.get(code, [])), latest_date),   # 第 35 輪 F35-1：股利（同個股 JSON 的 dv）
**osc_stats(o, h, l, c, af)}
```

- `dividends()` 是純函式，同樣的輸入得到同樣的結果。每檔多算一次，只是對最多 256 列跑幾個事件，2,000 檔加起來可以忽略。
- 個股 JSON、`latest.json` 都不變；`screen.json` 只多 5 欄。

### 2-3 大小

- 原型 `screen.json`：411 KB → 463 KB（＋52 KB）。比分析師估的 30～40 KB 多，主要是 `dvd` 的日期字串。仍在可接受範圍；`screen.json` 只在排行、選股、自選頁載入。

## 三、前端（F35-2～F35-4）

### 3-1 衍生欄（`screenRow`）

| 欄 | 算法 |
|---|---|
| `dva` | 除息至今天數 = `screen.json` 資料日 − `dvd`（日曆天，UTC 解析，整數） |
| `dvg` | 尚未填息時：今天原始收盤 ÷ `dvp` − 1（%）；已填、中斷、今天沒有收盤 → `null` |

- 用 `latest.json` 的原始收盤 `c`，不用還原價（R1）。
- `screen.json` 沒載入時不算（自選頁「資金」模式不受影響）。

### 3-2 欄位（`SCR_COLS`）

| 鍵 | 欄名 | 排序值 | 顯示 | 預設方向 |
|---|---|---|---|---|
| `dv` | 最近除息 | `dva` | `09/16` ＋第二行「6 天填息」／「未填息」／「中斷（減資）」 | 遞增（近的在前） |
| `dvg` | 距填息價 | `dvg` | `-25.00%` | 遞增（差最多的在前） |

- `dv` 欄的數字是天數，不依正負上色：在既有清單後面加 `|| k === 'dv'`，不改原本的字面（`test_iter12:90` 鎖定）。

### 3-3 選股條件（「基本面」組，殖利率之後、淨值比之前）

| id | 標籤 | 符合 | 顯示欄 |
|---|---|---|---|
| `dvk` | 近一年有現金配息 | `dvk ≥ 1` | 最近除息 |
| `dvf` | 最近一次已填息 | `dvn` 是數字 | 最近除息 |
| `dvu` | 最近一次尚未填息 | 有 `dvd`、沒有 `dvn`、沒有 `dvx` | 最近除息、距填息價 |
| `dvr` | 近 {30／60／90} 天內除息 | `dva ≤ N`；預設 60 | 最近除息 |

- 「已填息」「尚未填息」有游標提示 `DV_TITLE`。
- 殖利率條件 `cols` 從 `['dy']` 改成 `['dy', 'dv', 'dvg']`（F35-3）；「價值高息」組合的條件字串不變。
- 不新增選股組（`SCREEN_GROUPS` 由 `test_iter18:116` 鎖定）。
- id 不和既有條件、`o`／`od`／`ps` 衝突；網址條件、重新整理保留沿用既有機制。

### 3-4 排行「近期除息」（F35-4）

- `RANKS`：`['dv', '近期除息', 'dva', 1, 'x']`，放在殖利率後；`RANK_GROUPS` 基本面為 `['ry', 'dy', 'dv', 'pe']`。
- `RANK_FILTER.dv`：`dva ≤ 90`。排序沿用排行程式：`dir × (a − b)`（由近到遠），同天依成交額。
- `RANK_COLS.dv = ['dv', 'dy']`；另外殖利率排行 `RANK_COLS.dy` 也加 `'dv'`（和選股的殖利率條件一致）。
- `rankKeyCol` 對非信用、借券排行一律回傳 4，新排行不用改；`test_iter13` 的逐排行檢查通過。
- 頁尾在「近期除息」時多一段：「近期除息 = 近 90 天內除息或除權息，依除息日由近到遠。」＋ `DV_NOTE`。

### 3-5 說明文字

- `DV_NOTE`（選股頁說明最後、近期除息排行頁尾）：
  > 股利條件只看近 365 天最近一次除息或除權息（純配股不算），季配、半年配只看最近一次：填息 = 除息當天起原始收盤回到除息前收盤，填息天數含除息當天；還沒填息就遇到除權、減資等股本變動，標「中斷」。股價資料起點以前的除息不在範圍內。殖利率用去年股利 ÷ 今天收盤，股價下跌時殖利率會變高。
- 選股頁原本的說明文字一字不改，只在最後接上 `${DV_NOTE}`。
