## 一、本輪目標

讓個股頁的價格「講真話」。日線滿 52 週後，分割、減資、除權股的「52 週高／低」、K 線、均線、MACD、技術訊號都因為價格沒有還原而嚴重失真（緯穎 6669 的 52 週高 7,800、現價 1,810；寶雅 5904 的 767 對 72.5）。本輪以**還原價格與事件標記**為主軸，連帶修正同一段程式造成的漲跌錯誤（不比價日、前一日無成交）、股本變動後的本益比／殖利率、資料不足時仍下結論的技術訊號。功能面只加一項資料現成、端點已確認的 **A2 官方三大法人金額**，把首頁頭條數字從估算值換成官方值。

### B1 能否在本輪完成：評估結論

**可以完成「核心」，「延伸」延後。** 理由：

1. **上市的三種事件都已有端點，而且請求很少**：本次實測確認 `TWT49U`（除權息）、`TWTAUU`（減資）、`TWTB8U`（面額變更）都可以用日期區間查詢。分析師擔心的緯穎 6669 其實是 **2026-09-02 除權**（權值＋息值 5,185，參考價 2,614.99），就在 `TWT49U` 裡；8422 可寧衛、7780 大研生醫、6949 沛爾生醫在 `TWTB8U`；減資股在 `TWTAUU`（一年 20 筆）。補抓一年約 15 次請求、1～2 分鐘。
2. **上櫃不需要新端點**：參考價 = 收盤 − 官方漲跌。資料庫實查，寶雅 5904 的 8/10（720 → 72）、華義 3086 的 4/20（325 → 32.5）、合騏 8937、強生 4747、智通 8932 都能用這個方法反推，減資造成的參考價上調（例如 3152 璟德 6/30：208 → 360）也一樣。
3. **計算集中在匯出端**：還原係數只需要「事件日、前收、參考價」，在 `export.py` 逐檔計算即可，前端只要換資料來源、加標記與切換。
4. **延後的部分**：填息天數、成交量與法人張數還原、除權息行事曆、櫃買 `tpex_exright_daily` 交叉核對。這些不會造成畫面上的錯誤數字，延後不影響「消除誤導」的目標。

### B1-核心. 除權息／減資／面額變更：還原 K 線與 52 週高低、事件標記（優先 1，解決 P12）

- 要解決的問題：價格未還原，分割／減資／除權股的 52 週高低、K 線、MA、MACD、技術訊號失真（6669 52 週高 7,800 vs 現價 1,810；5904 767 vs 72.5；3086 337.5 vs 25.65；8422 250 vs 24.7）。週／月線資訊列在事件所在週期顯示約 −66%～−90% 的假漲跌。
- 範圍內：

    - 除權息：`https://www.twse.com.tw/rwd/zh/exRight/TWT49U?startDate=YYYYMMDD&endDate=YYYYMMDD&response=json`，取「資料日期、股票代號、除權息前收盤價、除權息參考價、權值+息值、權/息」。
    - 減資：`https://www.twse.com.tw/rwd/zh/reducation/TWTAUU?startDate=&endDate=&response=json`，取「恢復買賣日期、股票代號、停止買賣前收盤價格、恢復買賣參考價」。
    - 面額變更：`https://www.twse.com.tw/rwd/zh/change/TWTB8U?startDate=&endDate=&response=json`，欄位同上。
    - 只保留 `is_valid_stock_code()` 通過的代號；請求一律經過 `fetch.request`。
  - **資料來源（上櫃）**：不打新端點。以 `daily_prices` 反推：參考價 = 收盤 − 官方漲跌；參考價 ≠ 前一個有成交日的收盤時，視為一次調整事件。是否寫入事件表或在匯出時即時計算，由 SA 決定，但前端拿到的格式要與上市一致。

  - **還原計算**（匯出端）：事件係數 f = 參考價 ÷ 事件前收盤；某日的還原價 = 原始價 × 該日**之後**所有事件係數的乘積（向後還原，最新收盤不變）。開高低收都還原；成交量、法人張數**不還原**（列為 B1-延伸）。

    - 個股 JSON 加上事件清單（日期、類型、前收、參考價），以及前端還原所需的資料（匯出係數或事件清單由 SA 決定；個股 JSON 總大小增加 ≤ 5%）。

### P14. 不比價日與前一日無成交的漲跌改為正確值（優先 2，含 P11）

- 要解決的問題：`export.py` 以「官方漲跌 0 且收盤 ≠ 前收」判斷上市不比價，造成兩種錯誤：(a) 真正的除權息日，`latest.json` 的 `ch`／`p` 是 0、被算成平盤，K 線資訊列只能顯示「不比價」（P11）；(b) 前一日無成交的股票被誤判成不比價，首頁、排行顯示 0.00%（P14，10/30 有 1213 大飲、9918 欣天然、7732、8481、8487 共 5 檔）。
- 範圍內：
  - 上市股的漲跌改為：
    - 事件表有當日事件 → 漲跌 = 收盤 − 參考價，漲跌幅 = 漲跌 ÷ 參考價。
    - 前一個資料列無成交（且非事件日）→ 漲跌 = 收盤 − 最後成交日收盤，並匯出該日期，畫面 tooltip 註明「相對 MM/DD 收盤」。
    - 兩者皆不符、官方漲跌仍為 0 且收盤 ≠ 前收 → 維持現有「不比價」處理（B1 驗收 9 的未對到清單）。
  - 套用位置：`latest.json` 的 `ch`／`p`、上市漲跌家數、個股 JSON 的 `prices.ch`（K 線資訊列）、個股頁標頭。
- 範圍外：上櫃股（官方漲跌已相對參考價，無此問題）；前一日無成交時的「昨收」指標卡定義（維持現狀）。
- 驗收條件：
  1. 以 10/30 資料，1213 大飲在首頁／排行／個股頁顯示 **−0.07（−0.94%）**，相對 10/28 收盤 7.44，看得到「相對 10/28 收盤」的說明；另外 4 檔同樣不再是 0.00%。
  2. 10/30 上市漲跌家數：上述 5 檔依實際漲跌重新歸類，上漲＋下跌＋平盤合計與修改前相同（1,085）。
  3. 2317 個股頁日線游標移到 2026-07-02（除息日），資訊列漲跌 = 收盤 − `TWT49U` 參考價，不再顯示「不比價」；6669 的 9/2 顯示 −4.99（−0.19%）。
  4. 單元測試涵蓋三種分支（事件日、前一日無成交、仍無法判定），並驗證漲跌家數的歸類。
  5. **README 已同步更新**（「不比價日顯示不比價」的說明改為新規則）；本項沒有新指令或資料表，`__main__.py` 不需修改。
