## 七、不列缺陷的觀察

1. **錯誤訊息是 Python 原文**：例如群益回應的 `weight` 是 null 時，顯示「holdings.00982A 失敗：type NoneType doesn't define __round__ method」。
   - 影響只限該檔，沒有 Traceback，和第 5 輪統一缺欄位時的行為相同。
   - 可讀性略差，但不影響判斷。
2. **5 日合計的範圍**：只計入「最新或前一持股日」有持有的股票。
   - 例如某檔 ETF 在 3 天前就已出清，它的 −張數不會出現在 5 日合計裡。
   - 這和個別持股頁的 `d5`（只對目前持有的列計算）一致，手算核對也是用同一個口徑。建議第 8 輪在 README 補一句說明。
3. **群益伺服器偶爾回應超過 30 秒**：補歷史 596 次中有 22 次逾時，都在重試後成功。
   - 日常每晚只有 4 次請求，影響很小。
   - 若之後連續失敗，只會影響群益 4 檔，其他資料不受影響。
4. **補歷史時 log 是空的**：輸出被緩衝，不是程式問題。PG 建議之後的長時間指令用 `python3 -u`。
