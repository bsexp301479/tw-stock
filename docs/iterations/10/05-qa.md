### 2. 2408 近 4 季：52.86 和 50.7 誰對（`logs/iter10_qa_e4.log`）

- **從累計值逐季手算**：
  - 2025Q4 單季 = 全年 2.13 − Q3 累計 (−1.45) = 3.58。
  - 2026Q1 = 8.41。
  - 2026Q2 = 23.38 − 8.41 = 14.97。
  - 2026Q3 = 49.28 − 23.38 = 25.90。
  - 合計 **52.86**，等於公式「本季累計 49.28 + 去年全年 2.13 − 去年同季累計 (−1.45)」，也等於 SQL 與 `stocks/2408.json` 的 `e4`。
- **PM 的 50.7** 是「11/06 收盤 343.5 ÷ 官方本益比 6.77 = 50.74」。用同樣方式看 2408 每天的隱含 EPS：
  - 9/21～11/03：每天都是 **25.77**，這段時間官方用的是截至 Q2 的近 4 季。
  - 11/04 起是 **50.70～50.74**，代表官方在 11/04 換成截至 Q3 的近 4 季。
- **差異原因：股數**。
  - 用累計淨利 ÷ 累計 EPS 推算加權股數：2024Q1～2026Q1 都約 30.8～31.1 億股；2026 上半年加權 32.6 億股，1～9 月加權 33.3 億股。2026 年有增資。
  - 近 4 季歸屬母公司淨利 = 163,878,695 + 6,613,772 − (−4,479,418) = 174,971,885 千元。除以 50.74 得約 **34.5 億股**。
  - 截至 Q2 的近 4 季淨利 88,908,049 千元 ÷ 25.77，同樣約 34.5 億股。
  - 所以官方本益比的 EPS = 近 4 季淨利 ÷ 最新股數（增資後約 34.5 億股）。本輪的 EPS 是各期公告 EPS（各期加權股數）相減後加總。增資讓股數多了約 4%，官方 EPS 因此低約 4.1%（52.86 → 50.7）。
- **全市場對照**：
  - 有 115Q3 且官方本益比 > 0 的 350 檔，官方隱含 EPS ÷ SQL 近 4 季的中位數是 0.9998。
  - 275 檔在 ±3% 內。偏離大的多是面額變更或股本變動（例如 5904、6669），或官方還沒換成 Q3 的股票。
  - 2303 是 0.9955，2408 是 0.9599。
- **結論**：
  - 依設計 1-8 的定義（累計 EPS 相減），**52.86 正確**，畫面與匯出都是這個值。
  - PM 的 50.7 也不是錯，是官方口徑（最新股數）。兩者差異正是設計與畫面口徑說明寫的「期中有增資或減資時，相減的 EPS 會和公司公告的 EPS 略有差異」。
  - 本驗收依 PM「不同時以 SQL 為準」判定通過。
  - 觀察：對增資股來說，「本益比 = 股價 ÷ 近 4 季 EPS」用畫面的 52.86 算會得到 6.50，不是官方的 6.77；見第七節觀察第 1 點。

### QA-01（低，顯示文字）：季報柱狀圖的滑鼠提示「轉盈」只在去年同季也在 8 季內時才出現

- 重現步驟：
  1. `python3 -m twstock serve --port 8001 --no-browser`，開啟 `http://localhost:8001/#/stock/2408`。
  2. 滑鼠移到季報卡柱狀圖的「25Q3」柱，或在主控台執行 `[...document.querySelectorAll('#finBox .fb')].map(b => b.title)`。

### 不列缺陷的觀察

1. **增資股的近 4 季 EPS 和官方本益比的口徑不同**（第三節第 2 點）：
   - 2408 畫面寫「近 4 季 EPS 52.86」，官方本益比 6.77 對應 50.74。使用者若自己用 343.5 ÷ 52.86 會得到 6.50。
   - 口徑說明已寫「期中有增資或減資時，相減的 EPS 會和公司公告的單季 EPS 略有差異」。但 2408 的差異（4%）主要來自官方用最新股數，不是單季相減。
   - 建議之後在口徑說明補一句「官方本益比以最新股數計算，增資股的近 4 季 EPS 會比官方低」。不影響本輪驗收。
2. **選股的 EPS 年增顯示 2 位小數**（例如「+77.40%」「+261.30%」），資料是 1 位。原因是沿用既有 `spct`，營收年增欄也是同樣寫法，畫面內部一致。
3. **選股「毛利率」「毛利率年增」欄沒有季別小字**：季別混雜時，同一欄可能混有 Q2、Q3。設計 7-2 只要求 `eq`、`ey` 加小字，屬設計範圍內；同一列的 `eq` 已標季別。
4. **`04-dev.md` 的「財報優於去年」241 檔**，QA 實測與獨立計算都是 239 檔（`tv` ≥ 0.5、`ey` ≥ 20、`gmy` ≥ 0、排除處置與無成交）。資料沒有變（`screen.json` MD5 相同），推測是 PG 記錄時的條件或排除狀態不同。不影響驗收。
5. **12/01 只有金控齊、銀行等金融業未齊、總數 ≥ 98% 時，`check` 判 ✅ 並停止收集**。這是 PM 收齊條件第 2 條「或已過金融業截止後第一個交易日」的設計行為。截止後仍沒有公布的金融業公司，窗口內不會再補，要靠 `history … --only financials --force`。
6. **2881 2025Q2 單季淨收益 3,794,962 千元、EPS 0.49**，看起來異常，但累計值就是這樣（Q1 108,974,429 → 上半年 112,769,391），不是程式錯誤。季報卡的年增（+771.4%）因此很大，屬真實資料。
