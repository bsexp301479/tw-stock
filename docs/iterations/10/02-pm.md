### F10-1. 季 EPS 收集、`check` 一行與個股季報卡（優先 2，B5-1）

- 要解決的問題：
  - 網站沒有 EPS，使用者看不出「本益比一年最低」是股價跌還是獲利增。
  - 官方 OpenAPI 的綜合損益表是**年初至今累計**（107／107 家驗證），而且只保留最新一季，做不出單季 EPS 與年增。
- **資料來源**（SA 依此設計）：
  - mopsov `POST https://mopsov.twse.com.tw/mops/web/ajax_t163sb04`，參數 `TYPEK=sii|otc`、`year=民國年`、`season=01～04`、`step=1`、`firstin=1`、`off=1`、`isQuery=Y`、`encodeURIComponent=1`（分析師第七節 #3）。
  - 一個回應包含該市場全部業別的 6 張表（`table.hasBorder`），每季每市場 1 次。經過 `fetch.request`；舊站的安全性封鎖頁沿用 `revenue.py` 既有判斷。
  - 歷史季別與當季都用同一個解析器。OpenAPI 12 個端點的備援**第一版不做**。
- **資料表** `quarterly_financials`（新表；欄名、型別以分析師 2-2 為基礎，SA 定案）：
  - 存**累計值**，不存單季值；單季值在匯出時相減，公司更正累計值時不會留下不一致。
  - 唯一鍵 `(stock_id, fin_year, fin_quarter)`，`fin_year` 用西元年。重複寫入 = MERGE 覆寫（更正財報），但「首次收錄日」不變。
  - `industry_tbl`：記錄解析自哪一張表（一般業／金控／銀行／證券／保險／其他）。
  - **首次收錄日**：PM 傾向允許 NULL——補抓指令寫入的列為 NULL，季報季窗口的日常收集寫入當天日期；MERGE 更新時不覆寫既有值。理由：畫面不能把「補抓日」當成「公布日」。SA 可改用其他做法，但要符合驗收 #6。
  - 只寫入 `stocks` 已有的股票（和月營收相同）；略過的家數要印出來。
  - `setup-db` 可重複執行：既有資料庫上建出新表，第二次執行不報錯、不改資料。
- **業別欄位對應**（PM 原則；SA 依 6 張表的實際表頭定案，PM 已列在第五節第 3 點）：
  - 所有業別都要有：**淨利歸屬於母公司業主**、**基本每股盈餘**。EPS 欄名用「基本每股盈餘」前綴比對（保險業沒有「（元）」）。
  - 一般業：營業收入 → `revenue`；營業毛利（毛損）淨額 → `gross_profit`（分析師試算用的就是「淨額」）；營業利益（損失）→ `op_income`。
  - 金融業與其他業：**沒有毛利**（`gross_profit` = NULL）；營益（`op_income`）只在表內有「營業利益」欄時存（證券、保險），其餘 NULL；收入欄的對應（金控「淨收益」、證券「收益」、其他「收入」；銀行沒有合計欄、保險沒有收入欄）由 SA 決定是存 NULL 或明確定義的計算，**不可猜**。
  - 畫面：金融業不顯示毛利率；營益率只在有值時顯示。選股的毛利率條件不納入金融業（F10-2）。
- **單季相減規則**（匯出時計算）：
  - Q1 單季 = Q1 累計。
  - Q2、Q3 單季 = 本季累計 − 上一季累計。
  - **Q4 單季 = 全年（`season=04` 的累計）− Q3 累計**。年報截止日是 3/31，Q4 單季要到 3 月底以後才會齊。
  - 上一季累計缺（新上市、該季沒有資料）→ 該季單季為 null，**不可**用累計值頂替。
  - EPS、營收、毛利、營益、淨利都用同一套規則。毛利率 = 單季毛利 ÷ 單季營收；單季營收 ≤ 0 時毛利率為 null。
  - 近 4 季 EPS = 本季累計 + 去年全年 − 去年同季累計（四項都要有，否則 null）；一年前的近 4 季同理往前推一年。
  - 單季 EPS 年增 % = (本季 − 去年同季) ÷ |去年同季|；**去年同季 ≤ 0 時為 null**（畫面可寫「轉盈」「轉虧」，SA 定）。
  - 口徑說明一句：期中有增資或減資時，相減的 EPS 會和公司公告的單季 EPS 有小差異（加權股數不同）。
