- 符合「本益比位置 ≤ 10% 且股價 ≥ 52 週低點 1.5 倍」的有 **143 檔**（約 10%），大多是記憶體、載板、PCB。
- 投資人情境：崩跌第 4 天打開南亞科，看到「本益比一年最低」，容易以為「已經很便宜」。但本益比低的原因是近 4 季 EPS 大增：2025-11-06 官方沒有列本益比（近 4 季虧損），11/06 反推約 50.7 元（343.5 ÷ 6.77）。欣興同期從 2.09 元升到 19.32 元。景氣循環股在獲利高峰時本益比最低，這是常見的陷阱。

- 反推口徑：近 4 季 EPS = 當天收盤 ÷ 官方本益比（`q12.py`）。
- 結論：位置本身沒有算錯，但**單看位置會誤導**。P24 先補一句說明，B5-1 讓「近 8 季 EPS」和估值放在同一頁。

### 1-3 本益比中位數下降中，EPS 更新占多少

官方本益比 = 收盤 ÷ 近 4 季 EPS，所以「收盤 ÷ 本益比」可以反推出官方使用的近 4 季 EPS。把 EPS 固定在 10/20 的值，只讓股價變動，重算 11/06 的中位數：

| 市場 | 10/20 實際 | 11/06 實際 | 11/06（EPS 固定在 10/20） | EPS 更新造成的部分 |
|---|---|---|---|---|
| 上市 | 16.97 | 15.36 | 15.51 | 約 0.15（下降 1.61 的 9%） |
| 上櫃 | 19.44 | 16.94* | 17.27 | 約 0.33（下降 2.50 的 13%） |

\* 這裡的上櫃中位數只計當天有收盤的股票（664 檔），所以和網站的 17.11（674 檔）不同。比較的是同一組股票，口徑一致。

- 反推 EPS 變動超過 3% 的家數（上市＋上櫃）：10/21 1 家 → 11/04 38 家 → 11/05 55 家 → 11/06 **73 家**；10/21 起累計 255 家，和 OpenAPI 的 158＋123 = 281 家接近。由此可見，**官方本益比在公司公布財報後 0～1 個交易日內就會更新**。
- 對網站的意義：11/10～11/14 會有上千家的 EPS 更新。估值卡的「一年最低」到時會有較大一部分來自 EPS，不全是股價下跌。說明已經寫了，但 B5-2 若能加上「本季已公布 N 家」，會更清楚。

**單季或累計的證據**：OpenAPI 11/05 的 108 家裡，有 107 家的 1～9 月月營收齊全。這 107 家的「營業收入」都等於 1～9 月營收加總（誤差 < 5%），沒有一家等於 7～9 月加總。

- 例：卜蜂（1215）營業收入 21,866,426（千元）= 1～9 月營收 21,866,426；7～9 月只有 7,464,783。
- mopsov 115Q2 卜蜂營業收入 14,401,643，等於 1～6 月。21,866,426 − 14,401,643 = 7,464,783，**正好等於 7～9 月營收**。
- 所以「單季 = 本季累計 − 上一季累計」，Q1 單季就是 Q1 累計，Q4 單季 = 全年 − Q3 累計。

- 風險：

  - mopsov 是舊版站台，未來可能停用；月營收的 CSV 也依賴它，所以這個風險本來就存在。
  - 舊版站台偶爾會回傳安全性封鎖頁，`revenue.py` 已有判斷可以沿用。

### 2-2 需要的新資料表

建議新增一張表，不動既有表，所以**不需要 `backup` 之外的遷移**；建議仍先 `backup`。

```
quarterly_financials
  stock_id      INT  NOT NULL REFERENCES stocks(stock_id)
  fin_year      INT  NOT NULL          -- 西元年
  fin_quarter   INT  NOT NULL CHECK (1～4)
  revenue       BIGINT NULL            -- 累計（千元）；金融業為「收益」或「淨收益」，各業別對應由 SA 定
  gross_profit  BIGINT NULL            -- 累計；金融業 NULL
  op_income     BIGINT NULL            -- 累計；金融業 NULL 或依業別對應
  net_income    BIGINT NULL            -- 累計，歸屬於母公司業主
  eps           DECIMAL(10,2) NULL     -- 累計基本每股盈餘
  industry_tbl  NVARCHAR(10) NULL      -- ci/basi/bd/fh/ins/mim，解析時是哪一張表
  first_seen    DATE NOT NULL          -- 第一次收到的日期（當作「公布日」的近似值）
  updated_at    DATETIME NOT NULL DEFAULT GETDATE()
  UNIQUE (stock_id, fin_year, fin_quarter)
```

- **存累計值，不存單季值**。單季值在匯出時相減，這樣公司更正累計值時不會留下不一致的資料。
- 更正財報：和月營收不同，建議 **MERGE 覆寫**，但 `first_seen` 不變。
- 既有的 `stock_fundamentals.eps` 欄位：11/04～11/06 全部是 NULL（BWIBBU 沒有 EPS）。**它是沒有使用的欄位，本輪不刪**，只在這裡提出來，由 SA 決定是否在 README 註明。

  - 誰的單季 EPS 創新高（台光電、南亞科）。
  - 誰的毛利率轉弱（大立光、台達電）。
  - 誰的 EPS 低於上半年（聯電）。
- 年增需要去年同季，例如 114Q3 單季 = 114Q3 累計 − 114Q2 累計。補歷史後就有。

**B5-1：收集與個股頁**

1. 收集器：`t163sb04` 解析 6 種業別表 → `quarterly_financials`。`history` 補 113Q1～115Q2（10 季 × 2 市場 = 20 次）。
2. 收集時點（2-4）與 `check` 一行，例如「第 3 季財報：已收 281／1,950 家（14%），⏳ 公布期間（11/14 截止，金控 11/29）」。
3. 個股頁「季報」卡（在月營收下方）：
   - 近 8 季單季 EPS 柱狀圖，加上年增。
   - 最新一季的單季 EPS、累計 EPS 與年增、毛利率、營益率，以及公布日（`first_seen`）。
   - 近 4 季 EPS 合計，以及「一年前的近 4 季合計」。這一行直接回答 1-2 的問題，例如南亞科近 4 季 EPS 約 50.7 元，一年前為虧損。
4. 口徑說明：
   - 單季由累計相減。
   - 期中有增資或減資時，相減的 EPS 會和公司公告的單季 EPS 有小差異（加權股數不同）。
   - 金融業沒有毛利率。

**B5-2：選股與今日頁**

1. `screen.json` 新欄（每檔約 +20 B，約 +40 KB）：
   - `eq`：最新一季單季 EPS。
   - `ey`：單季 EPS 年增 %。
   - `e4`：近 4 季 EPS。
   - `gm`、`gmy`：毛利率與年增（百分點）。
   - `fq`：最新季別，例如 202603，和營收 `rm` 一樣，季別不同時加小字。
2. 選股條件：
   - 「單季 EPS 年增 ≥ X%」。
   - 「單季 EPS 創 N 季新高」。
   - 「毛利率年增 ≥ X 百分點」。
   - 「近 4 季 EPS > 0」。
   - 預設組合「財報優於去年」。
   - 「本益比低但 EPS 下滑」可以當作參考組合，用來找出景氣循環股的陷阱。
3. 今日頁估值卡加一行：「第 3 季財報已公布：上市 N、上櫃 M 家（近 5 日 K 家），本益比中位數會隨 EPS 更新而變動」。
4. **自算本益比：建議不做**。官方 BWIBBU 已經是「收盤 ÷ 近 4 季 EPS」。1-3 實測官方值在公布後 0～1 個交易日就會更新，自算只是重複。
   - 「最新單季 × 4」的年化本益比，對季節性產業（例如蘋果供應鏈）會誤導，不建議放。
   - 真正有價值的是「近 4 季 EPS 和一年前比較」，已經放在 B5-1 第 3 點。
5. 加權指數本益比（第 9 輪待辦）在 B5 之後才可能做，但還需要股數（`t187ap03_L` 實收資本額，未確認），列為 A10-延伸（第三節）。
