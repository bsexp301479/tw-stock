## 三、F23-3 js／css 版本參數

### 3-1 使用情境

- 使用者每輪更新後打開網站，常遇到「新資料＋舊程式」：
  - 第 22 輪 QA 推算舊 `app.js` 搭新 `latest.json` 時，新訊號頁會顯示「載入失敗」。
  - 第 15、18～22 輪的「待上線確認」都有一條「強制重新整理即可」。
- 目標是更新後**一般重新整理或重新打開**就拿到新程式，不必知道要強制重新整理。

### 3-2 現況與根因（8001 實測）

| 檢查 | 結果 |
|---|---|
| `index.html` 的引用 | `<link rel="stylesheet" href="app.css">`、`<script src="app.js" defer>`、`<script src="stock.js" defer>`，**沒有版本參數**。CDN 的 Plotly 2.35.2、Lightweight Charts 4.2.0 已經寫死版本 |
| 動態載入 | `app.js`、`stock.js` 中**沒有** `createElement('script')`、`import()`、`.src =`。`stock.js` 是 `index.html` 的靜態 `<script defer>`，不是由 `app.js` 動態載入。要改的只有 `index.html` 3 處 |
| 資料 JSON | `getJSON` 用 `fetch(url, { cache: 'no-cache' })`，每次都向伺服器確認，所以資料一定是新的 |
| 伺服器回應標頭 | `twstock serve`（`http.server.SimpleHTTPRequestHandler`）只送 `Last-Modified`，**沒有 `Cache-Control`、沒有 `ETag`** |
| 實際載入 | 頁面載入時 `app.css`、`app.js`、`stock.js` 的 `transferSize = 0`、`deliveryType = "cache"`：**沒有向伺服器確認，直接用快取** |
| 根因 | 沒有 `Cache-Control` 時，瀏覽器依 `Last-Modified` 自行估計可以快取多久（通常是「距上次修改時間」的 10%）。程式改了，舊快取在估計期限內仍會被直接使用；而資料每次都確認，於是新舊混用 |
| `index.html` 本身 | `Last-Modified` 是 11/03，**也可能被同樣地快取**。只在 `index.html` 加參數時，若瀏覽器用的是快取的舊 `index.html`，它引用的還是舊網址 |

### 3-3 做法評估

| 做法 | 內容 | 優點 | 缺點 | 行數 |
|---|---|---|---|---|
| A 手動版本號 | `app.js?v=23`，每輪 PG 改數字 | 最簡單 | 忘了改就失效，沒有東西會提醒；某一輪只改 css 也要記得改 | 3 |
| B `export` 時寫入 | `export` 計算雜湊並改寫 `index.html` | 不會忘 | `index.html` 在 git 裡，每晚的排程匯出會改到受版控的檔；`export` 的責任從「資料」擴大到「網站程式」；PG 改程式後不一定會跑 `export` | 約 15 |
| **C 內容雜湊＋測試** | `app.js?v=<sha1 前 8 碼>`；PG 改完程式後更新 `index.html`，新測試檢查 3 個參數**等於目前檔案內容的雜湊** | 檔案沒變就沿用快取；忘了改，測試會失敗；不動 `export` | 每輪 PG 多一個步驟（可在測試失敗訊息中印出正確的值，直接貼上） | 3＋測試約 15 |
| D `serve` 加 `Cache-Control: no-cache` | `cmd_serve` 的 handler 在 `end_headers` 前加這個標頭：每次都確認，沒變回 304 | 從根本解決本機的問題，包含 `index.html` | 只對 `twstock serve` 有效；使用者的 8000 是 11/03 啟動的程序，**要重新啟動一次**才生效 | 約 4 |

- **建議 C＋D**（D34-9）：
  - C 讓 js／css 在檔案改變時網址跟著變；D 讓 `index.html` 每次都向伺服器確認。兩者合起來，更新後一般重新整理就會拿到新程式。
  - 日後若部署到 Cloudflare Pages 等靜態主機，C 照樣有效。
- 上線注意：
  - 套用後第一次，若瀏覽器還拿著 11/03 的舊 `index.html`，**最後一次**需要強制重新整理。
  - 8000 要由使用者自己重新啟動 `serve`，D 才會生效。PG、QA 只能在 8001 驗證。
- 驗收方式（給 QA）：
  - 改一個 js 後，8001 一般重新整理，`performance.getEntriesByType('resource')` 中該檔的 `transferSize > 0`，網址帶新的 `v`。
  - 沒改的檔回 304，或沿用快取。
